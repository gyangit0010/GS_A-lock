The Big Idea: What is a Service?

The Service layer sits right between your HTTP Controllers and data Repositories, executing application rules.

Controller+Business Rules+Repositories=Service Layer

In simple terms: Controller receives the request. Service decides what should happen. For our GA_A-lock authentication application, the Service handles user registration checks, credential validations, password hashing, and token generation.

Creating and Wiring a Service

Spring manages services as beans using @Service and injects dependencies through constructors.

@Service
public class AuthService {
    private final UserRepository userRepository;
    private final PasswordEncoder passwordEncoder;
    private final JwtService jwtService;

    public AuthService(UserRepository userRepository, 
                       PasswordEncoder passwordEncoder, 
                       JwtService jwtService) {
        this.userRepository = userRepository;
        this.passwordEncoder = passwordEncoder;
        this.jwtService = jwtService;
    }

    public LoginResponse login(LoginRequest request) {
        // 1. Find user, 2. Check password, 3. Generate JWT
        return new LoginResponse("mock-jwt-token");
    }
}
Notice how clean this is: the service handles core authentication logic without dealing with HTTP endpoints or direct SQL queries.

Common Mistakes & Separation of Concerns

Keep your architecture maintainable by avoiding common pitfalls:

❌ Bad Practice
  • Stuffing business rules & SQL logic inside Controllers
  • Injecting raw repositories into controllers directly
  • Manually instantiating services with new AuthService() instead of letting Spring inject them
✅ Good Practice (Separation of Concerns)
  • Controller handles HTTP payload & requests
  • Service coordinates workflows & validations
  • Repository deals strictly with database communication

Glossary

Service Layer
The architectural layer that implements business logic and application rules.
@Service
A Spring stereotype annotation indicating that a class is a business service component managed in the Spring container.
Business Logic
The custom rules, verifications, and workflows that dictate how application data is processed.
Separation of Concerns
A design principle dividing a computer program into distinct sections so each section addresses a separate concern.
