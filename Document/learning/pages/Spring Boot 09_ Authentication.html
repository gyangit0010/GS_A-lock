What is Authentication?

The main purpose of GA_A-lock — proving who a user is, before Authorization, JWT and Spring Security build on top of it.

1. Proving your identity

Authentication = proving your identity. The application asks "are you really the user associated with this account?"
College ID analogy

A guard checks: is this really your ID? Does it belong to you? → identity verified. A web app checks email + password the same way.

Identification vs Authentication

"I am Gyan" (email) is identification. "Prove it" (password) is authentication.

2. Authentication vs Authorization

The single most important distinction in this whole series.

Authentication

Who are you? → establishes identity.
e.g. "You are Gyan."

Authorization

What are you allowed to do? → establishes permissions.
e.g. "Gyan has admin rights."

Authentication always comes first — you can't decide what someone's allowed to do until you know who they are. Authorization is Doc 10.

4. Hashing vs Encryption

Passwords are never stored directly — tap to compare the two.

Password verification never "reads" the original password back — it re-checks the submitted password against the stored hash, and only says match / no match.

5. Staying authenticated: Session vs Token

After login, how does the server know future requests belong to the same user?

GA_A-lock uses the JWT-based (token) approach — covered in full in Doc 11.

6. Authentication factors

Tap a factor category.

Combining factors is multi-factor authentication (MFA). GA_A-lock's first version uses just email + password.

Glossary

Authentication
Verifying who a user is.
Authorization
Deciding what an authenticated user can do (Doc 10).
Password hash
A one-way transformation of a password, stored instead of the raw password.
Session-based auth
Server stores session state; client holds a session identifier.
Token-based auth
Server issues a token (e.g. JWT) the client sends on every request; no server-side session storage.
MFA
Multi-factor authentication — combining more than one factor (know / have / are).
401 Unauthorized
The typical status code for failed authentication.
