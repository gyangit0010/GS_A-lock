What is Dependency Injection?

The concept that makes Spring code stop looking like magic.

1. What is a dependency?

An object a class needs in order to do its job.

public class AuthService {
    private UserRepository userRepository;
}

AuthService needs UserRepository to reach the database. So UserRepository is a dependency of AuthService.

Restaurant analogy

A chef needs ingredients. They shouldn't find a farmer, buy seeds, grow vegetables and build a farm first.

A class shouldn't be responsible for creating everything it needs either.

2. Without DI vs with DI

Toggle, and pick how many dependencies AuthService has.



Dependency Injection means providing an object with the dependencies it needs instead of making the object create them itself.







3. The Spring container and beans


Spring's IoC container creates, manages, connects, and controls the lifecycle of objects. Managed objects are beans. Add annotations to see Spring pick them up:






Spring Boot scans for @Component, @Service, @Repository, @Controller, @RestController and registers those classes as beans.







4. Constructor injection, step by step


What Spring does at startup. This is the style we'll use in GA_A-lock.


@Repository
public class UserRepository { }

@Service
public class AuthService {
    private final UserRepository userRepository;

    public AuthService(UserRepository userRepository) {
        this.userRepository = userRepository;
    }
}








Why private final?
The dependency is assigned once through the constructor and can't be replaced later, which makes the relationship clearer and safer.


Is @Autowired needed?
Not with a single constructor. Modern Spring uses it automatically. @Autowired means "find a suitable bean and inject it here."









5. IoC vs DI




Normally
Your class → creates objects → uses objects.


With Spring
Spring → creates objects → provides them to your classes. Control moved from your code to the container: Inversion of Control.




IoC is the broader principle: the framework controls object creation and management.
DI is one technique to achieve it: dependencies come from outside instead of being created inside.


IoC is the principle; DI is a common technique used to achieve it.

Glossary

Dependency Injection

Bean

IoC

Constructor injection
Dependencies are passed through the constructor. Our preferred style.


@Autowired
